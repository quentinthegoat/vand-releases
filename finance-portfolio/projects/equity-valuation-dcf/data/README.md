# Data

## What this is

`financials.json` holds six years (FY2019–FY2024) of income statement, balance sheet,
cash flow and market data for three **fictional** companies:

| Ticker | Name | Profile |
| :--- | :--- | :--- |
| MRDN | Meridian Beverage Group | mid-cap; margin squeeze in FY22, debt-funded acquisition, then deleveraging |
| CALD | Calder & Company | larger, slower, higher margin, low leverage |
| VSSL | Vessel Drinks | small, fast-growing, loss-making, equity-funded |

## Why fictional rather than real

Two reasons, in order of importance:

1. **Accuracy.** Reproducing a real issuer's line items from memory produces numbers that
   *look* authoritative and may be wrong. A wrong number presented as a real one is worse
   than an invented number presented as invented.
2. **Licensing.** Standardised fundamentals from a data vendor cannot be redistributed in
   a public repository.

## Why it is not just made-up numbers

The statements are generated by `build_statements.py` (in the portfolio's `data-lab/`
directory) from explicit operating drivers — revenue growth, gross margin, opex ratios,
DSO/DIO/DPO, capex, tax and financing decisions. Everything else is derived, and the
generator **refuses to emit a company** unless, for every single year:

```
total assets − total liabilities − total equity == 0     (to the cent)
closing cash on the balance sheet == closing cash on the cash flow statement
```

It also models the two circularities a real three-statement model has to handle: interest
income depends on the cash balance which depends on interest income, and a revolver draw
costs interest which changes the cash the year has to fund. Both are resolved by a
fixed-point iteration, exactly as a live model would with an iteration switch.

That is what makes the dataset useful for a valuation exercise: the accounts *articulate*.
Working capital genuinely ties to the day counts, the FY2022 acquisition genuinely shows
up in goodwill, and the revolver genuinely grows when dividends and buybacks exceed free
cash flow.

## Using a real company instead

Replace `financials.json` with the same structure, populated from filings:

| JSON field | 10-K source |
| :--- | :--- |
| `income_statement.revenue` … `net_income` | Consolidated Statements of Operations |
| `balance_sheet.*` | Consolidated Balance Sheets |
| `cash_flow.*` | Consolidated Statements of Cash Flows |
| `market.share_price`, `market_cap` | cover page / market data on the fiscal year-end date |
| `market.net_debt` | total debt including finance leases, less cash and equivalents |

No analysis code changes. `analysis.py` reads only the fields above.

## Schema

```
{ "MRDN": { "ticker", "name", "sector", "currency", "disclaimer",
            "opening_balance_plug",
            "years": [ { "year",
                         "income_statement": { revenue, cogs, gross_profit, sga,
                             research_development, depreciation, amortisation, ebitda,
                             ebit, interest_expense, interest_income, pretax_income, tax,
                             net_income, diluted_shares, eps, dividends_paid,
                             dividend_per_share },
                         "balance_sheet":    { cash, receivables, inventory, prepaid,
                             ppe_net, goodwill, intangibles, other_assets, payables,
                             accrued, debt_st, debt_lt, revolver, deferred_tax,
                             other_liabilities, share_capital, retained_earnings,
                             treasury, total_assets, total_liabilities, total_equity },
                         "cash_flow":        { net_income, depreciation_amortisation,
                             change_in_working_capital, deferred_tax_and_other,
                             cash_from_operations, capital_expenditure, acquisitions,
                             cash_from_investing, debt_issued, debt_repaid,
                             revolver_movement, equity_issued, dividends, buybacks,
                             cash_from_financing, net_change_in_cash, opening_cash,
                             closing_cash, free_cash_flow },
                         "market":           { share_price, market_cap, net_debt,
                             enterprise_value } } ] } }
```

Amounts are USD millions except per-share figures and share counts (millions of shares).

`opening_balance_plug` records the imbalance in the FY2018 opening balance sheet that had
to be absorbed into other assets or other liabilities before the model could roll forward.
It is reported rather than hidden, because an unreported plug is how a modelling error
becomes six years of quietly wrong numbers.
