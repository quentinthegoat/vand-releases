# Data

## Files

| File | Contents |
| :--- | :--- |
| `prices_daily.csv` | 2,608 trading days (2016-01-04 → 2025-12-31), 10 price series |
| `risk_free_daily.csv` | annualised short rate for each date, used for Sharpe/Sortino |
| `universe.csv` | ticker, description, factor exposures, annual expense ratio |

## This price history is simulated

The prices are **not market data**. They are generated by
`data-lab/generate_sample_prices.py` in the portfolio repository, from a documented factor
model, with a fixed seed — the same seed always produces a byte-identical file.

Two reasons for simulating rather than shipping real history:

1. **It has to run anywhere, for anyone, forever.** No API key, no network access, no
   licence. A reviewer clones the repository and gets identical numbers to the ones in the
   README, on any machine, in 2026 or 2036.
2. **Redistributing vendor price history is a licensing problem**, and the free sources
   that permit it are not stable enough to anchor a written analysis to.

## The generating process

```
r_i,t = alpha_i/252 + Σ_k beta_i,k · f_k,t + idio_i · z_i,t − expense_i/252
```

Seven factors: `EQ` (global equity), `RATE` (duration), `SIZE`, `VAL`, `FX`, `EM`, `GLD`.

The equity factor is not a random walk. It carries the stylised facts that make risk
analytics non-trivial:

- **GARCH(1,1) conditional variance** (ω, α=0.09, β=0.85) so volatility clusters, the way
  it does in real markets. Realised 12-month volatility in the sample ranges from 8% to
  19.5%.
- **Standardised Student-t(5) shocks**, so tails are fat. Realised excess kurtosis of the
  equity sleeves is +3 to +6.
- **Five planted regimes**: a Q4-2018 growth scare, a 2020 crash and recovery, a 2022
  rate-shock bear market, a 2023 recovery, and a 2025 correction. In the 2022 regime the
  rates factor is deliberately made to fall *with* equities, so the sample contains a
  period where bonds do not hedge — the failure mode that a purely Gaussian simulation
  never produces and that a portfolio analysis must be able to see.

Fund-level detail is modelled too: index-tracking funds are the index minus their expense
ratio plus tracking noise, which is what makes the ETF cost study meaningful.

### What this means for the conclusions

Anything about **method** transfers: the risk decomposition, the attribution arithmetic,
the rebalancing comparison, the tracking-error mathematics. Anything about **markets**
does not. The write-ups are explicit about which is which — for example, the equity
sleeves' 0.75–0.93 mutual correlations are an input to the simulation, not a finding about
the world.

## Running the same analysis on real data

This project uses the index and the three funds measured against it:

```bash
python fetch_real_prices.py \
    --tickers ^spx,spy,vti,vfmf \
    --names   IDXUS,LCAP,BRDX,SMRT \
    --start 2016-01-04 --out data/prices_daily.csv
python analysis.py
```

You must also update the expense ratios in `data/universe.csv` to the real funds' published
figures — the fee arithmetic is only as good as that column. And note the dividend warning
below with particular care here: comparing a price-return index against total-return funds
would make every fund look like it beat its benchmark by roughly the dividend yield.

`fetch_real_prices.py` pulls end-of-day closes from Stooq (free, no key) and writes the
same CSV layout. Two warnings, repeated from the script's own docstring because they
matter:

- Stooq's free series are not dividend-adjusted for every instrument. For total-return
  work on equity ETFs, check against the fund factsheet before quoting a CAGR: a 2%
  dividend yield omitted compounds to roughly a 22% error over ten years.
- Dates are intersected across tickers, so one short history silently truncates the whole
  panel. The script prints the resulting date range — read it.

You will also need a real risk-free series in `risk_free_daily.csv` (date, annualised
rate). Three-month T-bill yields from FRED (`DTB3`) are the conventional choice.

## Schema

`prices_daily.csv`

```
date,IDXUS,LCAP,BRDX,SMRT,SCAP,INTL,EMKT,BNDX,REIT,GOLD
2016-01-04,100.4618,100.4546,...
```

ISO dates, closing levels, all series based at 100 on day one. Weekends are excluded;
exchange holidays are not modelled, deliberately — a fake holiday calendar would invite a
reader to believe the panel is real.

`risk_free_daily.csv`

```
date,annualised_rate
2016-01-04,0.0040
```

Divide by 252 for a daily rate, which is what `analysis.py` does.
